# Шаблон отчета по лабораторной работе

## 1. Постановка задачи

- Цель работы: построить и проанализировать 2D-сечение функции потерь `L(theta)` для CNN на CIFAR-10, затем сравнить три квадратичные аппроксимации поверхности (`q1`, `q2`, `q3`) по метрикам ошибки.
- Основа метода: идея визуализации landscape из статьи Li et al., NeurIPS 2018 (filter-wise normalization для борьбы с масштабной неоднозначностью параметров).
- В этой версии покрыты: обучение `model1`, построение 2D/1D сечений, аппроксимации, метрики, визуализации и единый запуск через `run_pipeline.py`.
- Ограничения: расчёт поверхности дорогой по времени; на macOS возможны SSL-ошибки при `datasets.CIFAR10(download=True)`; качество численно зависит от платформы (CPU/GPU), но тренды сохраняются.

## 2. Теоретическая база

- Рассматривается локальная поверхность `f(alpha, beta) = L(theta + alpha d1 + beta d2)`, где `d1`, `d2` — случайные направления в пространстве параметров.
- Filter-wise normalization: для свёрточных весов направление нормируется по каждому выходному фильтру под норму соответствующего фильтра `theta`; это делает сравнение поверхностей более корректным.
- Типы аппроксимации:
  - `q1` (full quadratic): полная квадратичная форма с кросс-термином `alpha*beta`, оценка параметров через least squares + PD-проекция гессиана.
  - `q2` (diagonal quadratic): упрощение без кросс-термина (`b=0`), тоже с положительностью диагональных коэффициентов.
  - `q3` (hessian quadratic): локальная модель через градиент и конечные разности для `H11`, `H22`, `H12`.
- Почему метод уместен: задание требует оценить, насколько хорошо квадратики описывают локальную геометрию loss; 2D-сечение + 1D-профили дают и наглядность, и количественную проверку.

## 3. Данные и подготовка

- Датасет: CIFAR-10 (`torchvision.datasets.CIFAR10`), train/test split из torchvision.
- Предобработка:
  - train: `RandomCrop(32, padding=4)`, `RandomHorizontalFlip`, `Normalize(mean,std)`;
  - val/test: `ToTensor + Normalize(mean,std)`.
- Для ускорения оценки поверхности используется ограничение `max_batches` (по умолчанию 10 батчей), то есть подвыборка валидации.

## 4. Метод и реализация

- Пайплайн:
  1. обучение/загрузка чекпоинта (`src/train.py`);
  2. расчёт `surface_{model}_r{radius}.npz` (`src/surface.py`);
  3. аппроксимации (`src/quadratic_fit.py`);
  4. метрики 2D и 1D (`src/metrics.py`);
  5. графики (`src/plotting.py`).
- 2D-сечение: сетка `GRID_STEPS x GRID_STEPS` по `alpha,beta` в диапазоне `[-radius, radius]`.
- 1D-срезы: извлекаются из той же 2D-плоскости:
  - `f(alpha, 0)` (`alpha_axis`),
  - `f(0, beta)` (`beta_axis`).
- Ключевые настройки: `SEED=42`, `EPOCHS=30`, `BATCH_SIZE=128`, `LR=0.1`, `RADIUS_LIST=[0.1, 0.25, 0.5, 1.0, 2.0]`.
- Важно для воспроизводимости: при фиксированном `seed` направления `d1,d2` воспроизводимы и одинаковы для всех радиусов в одном запуске.

## 5. Эксперименты

- Сценарий 1: `model1`, 2D-сечение и аппроксимации `q1/q2/q3`.
- Сценарий 2: 1D-срезы вдоль `alpha_axis` и `beta_axis`.
- Метрики 2D (`r=0.1`, реальные значения из `metrics_vs_radius_model1.csv`):
  - `full_quadratic`: `RMSE=1.373e-05`, `L_inf=2.814e-05`, `RelRMSE=0.01372`
  - `diagonal_quadratic`: `RMSE=1.539e-05`, `L_inf=3.401e-05`, `RelRMSE=0.01538`
  - `hessian_quadratic`: `RMSE=1.194e-04`, `L_inf=3.355e-04`, `RelRMSE=0.11937`
- Метрики 1D (`r=0.1`, из `metrics_1d_vs_radius_model1.csv`):
  - `alpha_axis`, `q1/q2`: `RMSE=8.301e-06`, `RelRMSE=0.03542`
  - `alpha_axis`, `q3`: `RMSE=1.959e-05`, `RelRMSE=0.08360`
  - `beta_axis`, `q1/q2`: `RMSE=1.426e-05`, `RelRMSE=0.01952`
  - `beta_axis`, `q3`: `RMSE=5.350e-05`, `RelRMSE=0.07323`
- Примечание к источнику результатов: используемые числа в отчёте взяты из прогона на `RTX 3060` с полным режимом батчей.

## 6. Результаты

- На `r=0.1` обе регрессионные квадратики (`q1`, `q2`) аппроксимируют поверхность очень точно; `q3` заметно хуже по всем метрикам, что ожидаемо для FD-оценки с фиксированным `eps`.
- 1D-срезы подтверждают 2D-картину: ошибка `q3` в 2-4 раза выше, чем у `q1/q2`.
- По обучению `model1` ориентир валид. точности для 30 эпох: `~88-91%` (используется как sanity-check качества чекпоинта).
- Теоретическая интерпретация для сравнения архитектур: residual-связи (`model1`) обычно формируют более гладкий landscape, чем plain-модель (`model2`), за счёт более стабильной оптимизации и лучшей кондиции локальной геометрии.

## 7. Ограничения и риски

- Ограничение скорости: при полном `51x51` и нескольких радиусах вычисление поверхности затратное.
- Подвыборка `max_batches` ускоряет расчёт, но добавляет статистический шум в оценку loss.
- В текущем окружении есть SSL-блокер на загрузку CIFAR-10; из-за этого расширенный прогон по всем радиусам/моделям требует ручной подготовки датасета.
- Межплатформенная воспроизводимость: значения float не bit-exact между CPU/GPU, но сравнительные тренды сохраняются.

## 8. Выводы

- Пайплайн реализован и воспроизводим: от чекпоинта до surface/аппроксимаций/метрик/графиков.
- На доступных артефактах `r=0.1` лучшие аппроксимации — `q1` и `q2`; `q3` уступает по точности.
- Цель лабораторной достигнута частично: методологическая часть закрыта, но для финального отчёта нужно дозаполнить метрики по всем радиусам и, по возможности, по `model2`.
- Следующий шаг: устранить SSL-доступ к датасету (или вручную разложить CIFAR-10 в `data/raw/`) и выполнить полный прогон `RADIUS_LIST`.
